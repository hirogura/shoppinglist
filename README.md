# 買い物リスト管理シート

購入履歴を記録し、**同じ商品の最安値・平均・最高値**をすぐに確認できる Web アプリです。
「Amazon で買ったときの最安値と比べて、今は何円高い?」がすぐに分かります。

## 機能

- **購入履歴の登録** — 日付 / 商品名 / メモ / 購入店 / 今回の値段 / URL を 1 行で入力して登録
- **商品名のプルダウン** — 過去に入力した商品名を選択肢から選ぶ
- **メモ** — 型番や色・容量など、同じ商品名のまま違いが分かるように書き残せる
- **購入店のプルダウン** — Amazon / 楽天 / ヨドバシ / たのめーる を初期設定、それ以外の店も追加が可能
- **価格サマリー** — 商品名を入力すると、同じ商品の **最安値 / 平均 / 最高値 / 今回との差** を自動表示
- **履歴一覧** — 商品名が空のときは全履歴を日付の新しい順に表示
- **クリア** — 「追加」の右の「クリア」で入力内容を解除し、全履歴の表示に戻せる
- **編集** — 履歴の「編集」から商品名・メモ・日付・購入店・値段・URL を修正できる (商品名の付け替えも可)
- **設定** — 通販検索で使う Easyparser キー・楽天アプリ ID や「検索結果に画像表示」を画面から登録。設定はワークスペース外の `/opt/shoppinglist-data/search-config.json` に保存され、キーはブラウザへマスク済みの値しか返されません
- **通販で検索** — 「エクスポート」の左のボタンで右側に専用ペインを開き、Amazon / 楽天 / ヨドバシ.com を横断検索。検索結果と過去の購入商品を同じ画面で確認でき、結果から購入履歴フォームへ転記できる
- **エクスポート** — 購入履歴を JSON (バックアップ・再インポート用) / CSV (Excel 用) で書き出す
- **インポート** — エクスポートした JSON ファイルを読み込み、マージまたは全置換で取り込む
- **アップデート** — GitHub の公開リポジトリから最新版を取得 (設定不要で直接実行)
- **再起動** — サービス自身を再起動

## インストール

```bash
# 1. クローン
git clone https://github.com/<your-account>/shoppinglist.git /opt/shoppinglist

# 2. スクリプトを実行
cd /opt/shoppinglist
sudo ./deploy/install.sh
```

`install.sh` は以下を行います。

1. データ保存先 `/opt/shoppinglist-data` の作成
2. `npm install --omit=dev`
3. `systemd` ユニット (`shoppinglist.service`) の配置・有効化・起動
4. `tailscale serve --bg 3368` で tailnet 内に公開

| 項目 | 値 |
| --- | --- |
| ポート | 3368 (ローカル: `http://127.0.0.1:3368`) |
| サービス名 | `shoppinglist.service` |
| データ保存先 | `/opt/shoppinglist-data/shoppinglist.db` (SQLite / リポジトリ外) |
| ログ | `journalctl -u shoppinglist -f` |

手動で起動する場合:

```bash
npm start           # 既定で 3368 番ポートで起動
PORT=8080 npm start # ポート変更
```

## エクスポート / インポート

ヘッダーの「エクスポート」「インポート」からデータをファイルで出し入れできます。

**エクスポート** (ダイアログから形式を選択)

| 形式 | 内容 |
| --- | --- |
| JSON | バックアップ用。インポートでそのまま戻せます |
| CSV | Excel / Google シート用。`日付,商品名,メモ,購入店,値段,URL` (BOM 付き UTF-8) |

**インポート** (JSON ファイルを選択)

| モード | 内容 |
| --- | --- |
| マージ (既定) | 同じ ID の記録は更新し、無いものは追加します |
| すべて置き換える | 現在のデータを削除してから取り込みます |

商品名・日付・値段の形式が不正な行はスキップされ、実行結果として件数が表示されます。
インポート後も購入店の一覧には Amazon / 楽天 / ヨドバシ / たのめーる が保持されます。

## 通販で検索

ヘッダーの「通販で検索」を押すと、画面右側に専用ペインが開きます。左側の購入履歴はそのまま表示されるので、**検索結果と過去の購入商品を同じ画面で見比べ** できます。

- **検索** — キーワードを入力して「検索」ボタンを押します (日本語入力の確定では検索されません)。「すべて」を選ぶと設定済みのサイトを横断して検索し、タブで Amazon / 楽天 / ヨドバシ.com に絞ることもできます。
- **並び替え** — 安い順 (既定) / 高い順 / 評価順 / レビュー件数順。取得済みの結果を並べ替えるだけなので追加クレジットはかかりません。
- **画像表示** — 既定はテキストのみのシンプル表示。「設定」の「検索結果に画像を表示する」にチェックを入れると、商品画像のある検索結果にサムネイルを表示します。切り替えは即時に反映され、設定は再起動後も保持されます。
- **価格について** — 検索結果の価格は **目安** です。正確な価格は商品ページで確認してください (Easyparser の SEARCH は為替換算のドル表示が返ることがあります。約 160 円/ドルで円換算して表示します)。
- **購入履歴との照合** — Amazon の URL/ASIN が一致する商品、または商品名が近い商品に「購入履歴あり 最安 / 平均」バッジと価格差を表示します。照合はローカルの購入履歴だけで行うのでクレジットは消費しません。
- **購入履歴へ追加** — 検索結果のボタンを押すと、商品名・目安価格・購入店・URL・ASIN を記載したメモが左の入力フォームへ転記されます。内容を確認して「追加」を押すと登録されます (自動保存はしません)。
- **過去の購入商品** — ペイン下部に購入履歴を表示します。「この商品で検索」で同じ商品を再度検索でき、「フォームで編集」で既存の記録を修正できます。

### API キーの設定 (任意)

ヘッダーの「設定」を押すと、以下の項目を登録できます。入力内容はサーバーに送信され、**ワークスペース外** の `/opt/shoppinglist-data/search-config.json` (権限 0600) に保存されます。ブラウザへ返されるのは末尾 4 文字だけを残したマスク値なので、再表示時にキー全体が漏れることはありません。

| 項目 | 説明 |
| --- | --- |
| Easyparser API キー | Amazon 検索用の [Easyparser](https://easyparser.com/) API キー (SEARCH 1 クレジット) |
| 楽天 アプリケーション ID | 楽天市場 商品検索 API のアプリケーション ID |
| 円換算レート | ドル建てで返った検索価格を円に換算するレート (既定: `160`) |
| タイムアウト | 検索リクエストのタイムアウト ms (既定: `45000`) |
| 検索結果に画像表示 | チェックすると検索結果に商品サムネイルを表示 (既定: オフ) |

キーを空欄のまま「保存」すると既存の値は維持されます。削除したい場合は「保存済みのキーを削除する」にチェックを付けてください。未設定のサイトは直接検索リンクだけを表示し、API を呼びません。

環境変数でも設定できます (環境変数が設定ファイルより優先されます)。リポジトリを編集せず systemd のドロップインを使ってください。

```bash
sudo systemctl edit shoppinglist
# [Service]
# Environment=EASYPARSER_API_KEY=<キー>
# Environment=RAKUTEN_APP_ID=<アプリID>
sudo systemctl restart shoppinglist
```

| 変数 | 説明 |
| --- | --- |
| `EASYPARSER_API_KEY` | Amazon 検索用の Easyparser API キー |
| `RAKUTEN_APP_ID` | 楽天市場 商品検索 API のアプリケーション ID |
| `EASYPARSER_ENDPOINT` | Easyparser Realtime API の URL (既定: `https://realtime.easyparser.com/v1/request`) |
| `SHOPPINGLIST_USD_JPY` | ドル建て価格の円換算レート (既定: `160`) |
| `SHOPPINGLIST_SEARCH_TIMEOUT` | 検索のタイムアウト ms (既定: `45000`) |

ヨドバシ.com は公開 API がないため、常に直接検索リンクを表示します。残りクレジットは検索レスポンスに含まれる値を表示するだけなので、表示用の追加リクエストは発生しません。

## アップデート

画面右上の「アップデート」を押すと確認後にそのまま最新版を取得します。リポジトリURLやトークンの設定は不要です。

`origin` リモートの現在のブランチを `git fetch` し、`git reset --hard FETCH_HEAD` → `npm install --omit=dev` を実行して、完了後にサービスを再起動します。

未 push のローカルコミットがある場合は、勝手に破棄せず更新を中止します (安全のため)。
ローカルの変更を破棄してリモートに合わせたい場合は `POST /api/update` に `{ "force": true }` を指定してください。

| `SHOPPINGLIST_SEARCH_TIMEOUT` | `45000` | 検索リクエストのタイムアウト (ms) |

## API

| メソッド | パス | 説明 |
| --- | --- | --- |
| GET | `/api/state?name=` | 購入履歴・価格統計・商品名一覧・購入店一覧をまとめて取得 |
| GET | `/api/purchases?name=` | 購入履歴 (商品名指定時は該当のみ) |
| GET | `/api/stats?name=` | 指定商品の 最安値 / 平均 / 最高値 / 購入回数 |
| GET | `/api/settings` | 通販検索の設定状況 (キーはマスク済み) |
| PUT | `/api/settings` | 通販検索の設定を保存 (ワークスペース外の JSON ファイルへ書き出し) |
| GET | `/api/search/providers` | 検索サイトの設定状況・直接検索 URL・残クレジット (クレジット消費なし) |
| GET | `/api/search?q=&provider=` | 通販横断検索 (`provider`: `all` / `amazon` / `rakuten` / `yodobashi`) |
| POST | `/api/purchases` | 購入履歴の登録 (日付 / 商品名 / メモ / 購入店 / 値段 / URL) |
| PUT | `/api/purchases/:id` | 購入履歴の更新 (商品名・メモなどの修正) |
| DELETE | `/api/purchases/:id` | 購入履歴の削除 |
| GET | `/api/stores` | 購入店一覧 |
| POST | `/api/stores` | 購入店の追加 |
| GET | `/api/export?format=json\|csv` | データのエクスポート (添付ファイル) |
| POST | `/api/import` | データのインポート (body: `{ data, mode: 'merge'\|'replace' }`) |
| POST | `/api/update` | GitHub からのアップデート実行 |
| POST | `/api/restart` | サービスの再起動 |

## 構成

```
server.js          エントリポイント (Express)
src/db.js          SQLite (purchases / stores)
src/routes.js      API
src/git.js         GitHub アップデート処理
src/service.js     systemd 再起動
src/search.js      通販検索プロキシ (Easyparser / 楽天 / 直接検索リンク)
src/search-config.js 認証情報の保存先管理 (/opt/shoppinglist-data/search-config.json)
public/            フロントエンド (Vanilla JS / CSS)
deploy/            systemd ユニット・インストールスクリプト
test/              API・アップデート・フロント (E2E) のテスト
```

データはリポジトリ外の `/opt/shoppinglist-data/shoppinglist.db` に保存されます。
